请分析以下一批消费者评论（{batch_size} 条）的情感与观点，逐条输出。

【评论文本批次】
{batch_texts}

【输出格式】严格 JSON，results 数组长度必须等于评论数，index 对应批次编号：
{{
  "results": [
    {{
      "index": 0,
      "sentiment": "positive|negative|neutral",
      "sentiment_score": -1到1,
      "opinions": [
        {{"phrase": "打击感超爽", "sentiment": "positive", "sentiment_score": 0.8, "sentiment_confidence": 0.95, "is_core": true}},
        {{"phrase": "价格太贵", "sentiment": "negative", "sentiment_score": -0.6, "sentiment_confidence": 0.85}}
      ]
    }}
  ]
}}

【规则】
1. **逐句/逐方面扫描评论**，把每个独立讨论点都提取为一条观点，不要漏
2. 每条观点 = phrase（从原声提炼的短句，尽量保留原词）+ sentiment（观点情感）+ sentiment_score（-1到1）+ sentiment_confidence（0到1，对该观点情感判断的确信度）
   **phrase 优先提炼"具体维度"表述**（战斗/动作、画面/美术、剧情/叙事、音效/音乐、性能/优化、价格/内购、网络/服务器、外挂/反作弊、玩家社区等），并尽量保留能命中维度的关键词（如"打击感""boss战""画面糊""优化差""抽卡""挂多""卡顿"）
3. 每条评论至多一个 is_core=true（最重要观点）；**is_core 优先指向具体维度观点，而不是"好玩/垃圾"这类整体褒贬**；无则默认第一个
4. **sentiment / sentiment_score 表示整条评论的整体情感**（即使 opinions 为空也必须输出）
5. 整活/梗类评论 → phrase 保留原话即可（如"坟头草是绿的也算绿玩吗"）
6. **具体维度优先于整体褒贬**：评论里只要涉及了具体维度（战斗/动作/画面/剧情/性能/价格/网络/外挂/皮肤等），就必须把该维度提取为观点；"好玩""垃圾""神作"这类无具体场景的整体褒贬，**只在评论确实没有具体维度时才单独成一条观点**
7. **只有评论完全没有语义内容时**（纯乱码/纯表情/纯数字/纯时间纪念）→ opinions 为空数组；**"挂壁游戏""好好练枪"这类有明确指向的短评，必须有观点**
8. sentiment 只能是 positive/negative/neutral

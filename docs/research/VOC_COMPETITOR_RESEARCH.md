## 二、个人开发者的核心场景与目标

### 2.1 项目定位建议

| 定位           | 适用人群     | 价值主张                     |
| ------------ | -------- | ------------------------ |
| **学习项目**     | 初学者      | 学习NLP、数据采集、情感分析、大模型API集成 |
| **个人作品集**    | 求职/展示    | GitHub上的完整工程，展示技术深度      |
| **垂直兴趣分析工具** | 行业爱好者    | 比如：游戏评测情感分析、某品牌舆情追踪      |
| **轻量服务**     | 小团队/兴趣社群 | 提供给小型团队使用的能力             |

### 2.2 关键约束下的最优解原则

```
个人项目 = MVP（最小可行产品）+ 长期迭代
约束：
  预算：100~1000元/年 → 必须善用免费额度
  数据：<10K/月 → 单机能扛，无需分布式
  目标：学习与展示 → 代码质量、可读性、可分享性优先
  合规：学习研究为主 → 优先官方API，规避敏感爬虫
```

### 2.3 推荐功能范围（克制）

**做这些（核心功能）：**

- 数据采集（1-3个稳定数据源）
- 情感分析（调用免费/低成本大模型）
- 简单可视化（词云、趋势图）
- 关键洞察报告（每周/每月自动生成）

**不做这些（避免过度工程化）：**

- 实时预警（<10K数据量不需要）
- 复杂工单流转（个人项目无运维必要）
- 多租户/权限系统（单用户场景）
- 大规模分布式架构（杀鸡用牛刀）

### 3.4 数据采集的合规红线

| 行为                      | 风险等级 | 个人项目建议         |
| ----------------------- | ---- | -------------- |
| 抓取**公开可见**的内容用于**学习研究** | 低    | ✅ 可接受          |
| 绕过反爬机制（IP代理、签名伪造）       | 中    | ⚠️ 学习技术可，但生产慎用 |
| 大规模商业化采集                | 高    | ❌ 绝不建议         |
| 爬取用户隐私数据（手机号、地址）        | 极高   | ❌ 严格禁止         |
| 突破账号登录态采集               | 中高   | ⚠️ 仅自有账号       |
| 用于商业转售                  | 极高   | ❌ 严格禁止         |

> **个人开发者黄金法则**：
>
> 1. **数据量控制在 <10K/月**（属于个人研究安全范围）
> 2. **优先官方API**（B站、Steam、淘宝、京东都开放）
> 3. **爬虫仅用于学习研究**，且严格遵守平台robots.txt
> 4. **不存储用户隐私信息**
> 5. **GitHub项目添加明确免责声明**

## 四、技术栈推荐（个人版）

### 4.1 架构原则：能用免费就别花钱，能跑在笔记本就别上云

```
个人开发者的架构 = 单机 + Serverless + 免费额度
绝不推荐：Kubernetes、微服务、分布式集群
```

### 4.2 推荐技术栈（按数据规模）

#### 数据量 <1000条/月（最小配置）

```
数据采集：Python requests + 官方API
存储：SQLite（本地文件） / Notion API（个人知识库）
分析：Python + 调用大模型API
可视化：Streamlit / Jupyter Notebook / 静态HTML
部署：本机运行 / GitHub Pages
成本：0元
```

#### 数据量 1000-10000条/月（轻量配置）

```
数据采集：Python + Playwright + 定时任务
存储：PostgreSQL（本地） / Supabase免费版（500MB）
分析：Python + Transformers（小模型本地推理）
可视化：Streamlit / Gradio / Next.js + ECharts
部署：Vercel / 阿里云函数计算（按量付费）
成本：100-500元/年
```

#### 数据量 接近上限（推荐配置）

```
数据采集：Python + Playwright + GitHub Actions定时
存储：PostgreSQL / SQLite
分析：Python + Hugging Face模型本地推理
可视化：Streamlit Cloud（免费）/ Next.js
部署：GitHub Pages + GitHub Actions
成本：500-1000元/年
```

### 4.5 个人项目的成本测算示例

**场景**：每月采集5000条评论，每条评论约100字，做情感分析+主题分类+摘要生成。

```
输入数据：5000 × 100字 = 50万字 ≈ 75万tokens
分析输出：5000 × 50字 ≈ 37.5万tokens

使用DeepSeek-V3.2-Exp：
  输入成本：75万tokens × ¥2/百万 = ¥1.5
  输出成本：37.5万tokens × ¥3/百万 = ¥1.125
  月度总成本：约 ¥2.6
  年度总成本：约 ¥31

使用Qwen3-Flash：
  输入成本：75万tokens × ¥0.15/百万 = ¥0.11
  输出成本：37.5万tokens × ¥1.5/百万 = ¥0.56
  月度总成本：约 ¥0.67
  年度总成本：约 ¥8
```

> **结论**：即使是满额10K数据/月，AI分析成本也可控制在 ¥10-50/年，远低于预算上限。

## 六、MVP路线图（6个月）

### 阶段一：数据贯通（第1-2月）

**目标**：能稳定采集到数据，建立分析基线。

```
Week 1-2：项目初始化
  - 选定2-3个数据源（推荐：Steam + B站 + 微博）
  - 申请API Key（Steam、B站开放平台、微博开放平台）
  - 搭建项目框架

Week 3-4：第一个采集器跑通
  - 实现Steam游戏评论采集（最简单）
  - 实现B站视频评论采集（API直接调）
  - 数据落SQLite，每周采集100-200条

Week 5-8：第三个数据源接入
  - 微博API接入（门槛较高，需要OAuth认证）
  - 或小红书（蒲公英合作 / MediaCrawler学习用）
  - 完善数据清洗与去重
```

### 阶段二：分析深化（第3-4月）

**目标**：从原始文本中提取洞察。

```
Week 9-10：情感分析集成
  - 接入DeepSeek API（成本最低）
  - 测试Qwen3-Flash性价比方案
  - 对比本地模型（bert-base-chinese）

Week 11-12：主题分类与摘要
  - 利用大模型做主题聚类
  - 自动生成周报/月报摘要
  - 提取关键问题与高频痛点

Week 13-16：可视化完善
  - Streamlit仪表盘
  - 词云、情感趋势图、TOP问题榜
  - 输出HTML报告（可分享）

### 阶段三：作品化（第5-6月）

**目标**：让项目在GitHub上成为亮眼的作品。

```
Week 17-20：自动化与文档化
  - GitHub Actions定时任务

## 九、风险与注意事项

### 9.1 个人项目的特殊风险

| 风险           | 影响     | 应对策略                           |
| ------------ | ------ | ------------------------------ |
| **平台反爬升级**   | 数据采集中断 | 优先官方API，留有多个备选数据源              |
| **大模型API涨价** | 成本上升   | 同时接入2-3家API做备份                 |
| **数据合规风险**   | 法律问题   | 数据量<10K/月，仅学习研究用，**不公开传播原始数据** |
| **个人精力不足**   | 项目烂尾   | MVP优先，功能克制，迭代发布                |
| **求职市场认可度**  | 项目白做   | 注重代码质量、文档、可分享性                 |

### 9.2 不可触碰的红线

```
❌ 不要大规模商业化采集（>10K/天属红线）
❌ 不要爬取用户隐私信息（手机号、地址、身份证）
❌ 不要将采集数据用于转售
❌ 不要绕过账号认证采集他人数据
❌ 不要将原始数据公开发布到GitHub
```

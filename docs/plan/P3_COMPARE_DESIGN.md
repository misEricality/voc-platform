# P3 多目标横向对比 · 设计文档

> **用途**：P3（多目标横向对比，6 款游戏同看）的设计方案与实现指引。
>
> **关联文档**：[开发计划 DEVELOPMENT_PLAN.md](./DEVELOPMENT_PLAN.md) · [标注管线 ANNOTATION_PIPELINE.md](../architecture/ANNOTATION_PIPELINE.md) · [字段字典 DATA_FIELDS.md](../architecture/DATA_FIELDS.md)
>
> **状态**：✅ 设计已定稿（2026-08） · ✅ 原型卡片页已实现（game-compare.html） · ✅ Streamlit 图表对比视图已实现（2026-08-19）
>
> **核心结论**：P3 不做"现有看板加几个对比图"，而是做**一个独立的"多目标对比视图"**。三大动作 = **同表并列 / 偏差显形 / 口径防坑**。计划里的"每游戏一张雷达图"砍掉，换成"堆叠条 + 热力图 + 散点定位图"。

> **两个入口，别混**：`product/prototype/game-compare.html` 是**静态作品集封面**（发文件/挂 Pages，零服务器，给访客第一眼印象）；本文档的对比视图是 **Streamlit 分析工具**（`app.py` → 侧边栏「视图 → 多目标对比」，给自己深挖洞察）。二者同品牌、同数据，通过原型页的「打开分析看板 →」链接单向打通。

## 一、业务目标

在一个仪表盘里同时看到 6 款游戏的舆情对比，直接增量当前看板的洞察力：

- **玩家视角**：换游戏该看哪款？哪款口碑好、哪款在哪个维度上被骂？
- **行业视角**：6 款游戏在"主题 × 情感"上的差异化口碑格局。

**验收标准（对齐 M8 里程碑判据）**：打开对比页，10 秒内能回答三个问题——
1. 哪款口碑最好 / 最差？
2. 各自的主要痛点是什么？
3. 哪个主题上谁显著偏离均值？

| 游戏 | appid | 已分析 n |
|---|---|---|
| PUBG | 578080 | 2571 |
| Apex Legends | 1172470 | 1452 |
| 黑神话：悟空 | 2358720 | 1392 |
| 底特律：化身为人 | 1222140 | 713 |
| 巫师 3：狂猎 | 292030 | 466 |
| Counter-Strike 2 | 730 | 459 |
| Dota 2 | 570 | 433 |
| 文明 6 | 289070 | 398 |
| 光与影：33号远征队 | 1903340 | 270 |
| 星际拓荒 | 753640 | 148 |

> 共 10 款 Steam 游戏（原 6 款 + CS2 / Dota2 / PUBG / Apex）+ 1 条 B 站视频 = 11 个 target。
> 对比视图默认取这 10 款 Steam；B 站跨平台对比归 P5。

### 2.2 两个必须处理的硬约束

**① 样本量极不均**（148 ~ 2571，差 17 倍；补采后已无 n<100，原"小样本"约束基本解除）：
- 占比对比仍需带 **n 标注**，让读者感知样本量差异（星际拓荒 148 vs PUBG 2571）。
- `n < 100` 警示可放宽或移除，但 tooltip 仍显示 n。
- 排序 / 高亮可对 n 做轻惩罚。

**② 兜底桶"综合与元表达"占观点级 67.4%**（2026-08-18 词典扩充 + 存量重匹配后，基线 71.0%）：
- 不做处理，热力图仍被同一个大桶主导，对比价值锐减。
- **这一条不做，P3 就是白做。**
- 处理方式：热力图默认**排除该桶**（或置灰），仅在"整体褒贬"模式才显示。

### 2.3 数据侧利好

- `comment_opinions` 表天然支持"主题 × 情感"：每条观点含 `full_path`（L1/L2/L3）+ `sentiment` + `quote`，主题×情感热力图**无需新分析，直接聚合即可**。
- Steam 原生 `rating`（推荐 / 不推荐）是**玩家真实行为信号**，比 LLM 情感更"硬"，可作 KPI 与散点定位图的核心轴。

## 三、信息架构：独立视图，不塞进单目标页

现有看板是"**浏览单目标**"模式（逐目标深入阅读），P3 是"**比较多目标**"模式（同表并列）。认知方式不同，混在一起两边都做不好。

| 决策 | 说明 |
|---|---|
| 独立视图 | 侧边栏 `st.radio("视图", ["单目标看板", "多目标对比"])`，共用 repo 层 |
| 同源才可比 | 对比页**默认比 10 款 Steam 游戏**；B 站视频不进对比（跨平台对比归 P5） |
| 卡片页定位 | 原型 `game-compare.html` 封面卡片页保留为"作品集展示件"；对比页走**图表优先**（分析工具，非海报） |

### 视觉风格（与现有看板一致）

- 沿用现有原型 / 看板的 **Steam 蓝黑主题**：背景 `#0e141b`、面板 `#1b2838`、主色 `#66c0f4`、强调绿 `#a1cd44` / 红 `#e05c5c` / 黄 `#d9b54e`（见 `product/prototype/src/base.css` 与 `game-compare.css` 的 `:root` 变量）。
- 原型 `game-compare.html` 已按此主题实现（3 列卡片 grid + library_hero 封面 + 词云）；Streamlit 对比页也应对齐这组色值（Plotly `color_discrete_map` / 布局背景 / 字体）。
- 注意：`product/overview.md` 里的旧配色（#78A4CB 等浅色）已过时，以 `base.css` 的深色主题为准。

## 四、页面结构（从上到下，L1 概览 → L2 对比 → L3 下钻）

```
┌──────────────────────────────────────────────┐
│ ① 目标选择器（multi-select，默认 10 款，上限 10） │
├──────────────────────────────────────────────┤
│ ② KPI 行：每游戏一列卡片                         │
│    n / 本地推荐率 / 正·负占比 / 情感均分          │
├──────────────────────────────────────────────┤
│ ③ 口碑格局散点图（hero）                        │
│    X=本地推荐率  Y=情感均分  气泡=样本量          │
├──────────────────────────────────────────────┤
│ ④ 情感构成 100% 堆叠条（一游戏一条）             │
├──────────────────────────────────────────────┤
│ ⑤ 主题 × 游戏 热力图（可切 正/负/全部、           │
│    可切"占比 / 相对均值偏差"两种模式）            │
├──────────────────────────────────────────────┤
│ ⑥ 每游戏"负面痛点 TOP5"（L2/L3 观点路径）表格     │
├──────────────────────────────────────────────┤
│ ⑦ 下钻：点游戏/主题 → 跳转单目标看板             │
└──────────────────────────────────────────────┘
```

### ④⑤ 两个"对比利器"的设计要点

**③ 散点定位图（hero，最高性价比）**
- X = 本地推荐率（Steam 原生 rating，玩家真实行为）
- Y = 情感均分（LLM）
- 气泡大小 = 样本量（顺带暴露数据可信度）
- 一图回答"谁叫好又叫座 / 谁叫好不叫座"，是 P3 最"洞察"的视图，放最显眼位置。

**⑥ 负面痛点表（最实用的产出）**
- 按游戏列出负面观点最多的 L2/L3 路径（如"技术与性能/性能优化"）。
- 一屏看出"黑神话被骂优化、PUBG 被骂外挂"这类结论；**文字形式比图更可读**。

## 五、图表选型：对"雷达图 + 热力图"的修正意见

计划原交付物是"每游戏小雷达图（情感/体量/主题）+ 主题×情感热力图"。修正如下：

### 5.1 雷达图：砍掉，或降级为可选小图

- 把情感 3 类 + 体量 1 项 + 主题 10 类揉进一张雷达 = **维度堆砌**，可读性差。
- 雷达图**不适合跨图比较**：人对角度不敏感，6 张雷达摆一起谁也说不出差异。
- 我们的主题分布是偏态长尾（TOP 主题占大头），雷达会被单轴撑爆。
- 替代：情感构成用 **100% 堆叠条**（一游戏一根，一眼比三段比例）；主题用**热力图**，各自是更优形式。

### 5.2 热力图：方向对，但拆成两种模式

- **占比模式**：行 = 主题（L1，默认排除兜底桶），列 = 游戏，颜色 = 该游戏观点中该主题占比 → 回答"每款游戏的关注点分布"。
- **偏差模式（比较的灵魂，强烈建议加）**：颜色 = 该游戏该主题占比 − 6 款均值 → 回答"**黑神话在'叙事与世界观'上比平均水平高 X 个百分点**"这种真正的对比结论。

### 5.3 体量不要进图

体量（评论数）放 KPI 卡片 + 气泡大小即可，它与占比不是同一量纲，揉进同一张图是**伪对比**。

## 六、口径与坑（比图表更重要）

| # | 坑 | 处理 |
|---|---|---|
| 1 | 情感 vs 主题口径混用 | **情感用评论级**（`comments.sentiment`）；**主题用观点级**（`comment_opinions`，一条评论可多观点，更细且自带 sentiment）。页面标注口径。 |
| 2 | 跨源不可比 | 默认 Steam 6 款；B 站视频单独放。 |
| 3 | 样本量失真 | `n < 100` 标 ⚠️；tooltip 显示 n；比例排序/高亮对 n 做轻惩罚。 |
| 4 | 目标漏采 | 现有侧边栏"目标对象"从 `all_analyzed(limit=1000)` 前 1000 条里取 target 去重，**超 1000 条会漏**。对比页新增 `repo.list_targets()` 走 SQL GROUP BY，别再全表拉。 |
| 5 | 兜底桶淹没差异 | 热力图默认排除"综合与元表达"，避免 6 款游戏全是同一个大桶。 |

## 七、技术实现（对齐 2-3 小时预算）

### 7.1 存储层（`src/storage/db.py`）

新增方法，**SQL 聚合而不是 Python 全量过滤**（现 `app.py` 是 `limit=2000` 全量拉，11 目标会明显变慢）：

- `list_targets(platform=None) -> list[dict]`：目标清单 + 各自评论数 / 已分析数 / 本地推荐率（GROUP BY）。
- `opinion_matrix(targets, level, sentiment=None) -> DataFrame`：主题 × 目标 聚合（观点级）。
- `sentiment_ratio_by_targets(targets) -> DataFrame`：评论级情感构成（positive/neutral/negative 占比）。

### 7.2 可视化层（`src/visualizer/charts.py`）

新增，复用现有 `build_summary_dataframe`：

- `sentiment_stacked(df_or_matrix) -> fig`
- `topic_game_heatmap(matrix, mode="ratio"|"deviation") -> fig`
- `position_scatter(targets_df) -> fig`

### 7.3 应用层（`app.py`）

- 拆出 `render_compare()` 函数，侧边栏 `st.radio` 切换视图。
- 对比页**一次查询全部目标**，不重复 `init_db`。
- 全部用 Plotly：`px.bar`（堆叠）+ `go.Heatmap` + `px.scatter`，**不引新依赖**。

### 7.4 可选增强（超出 2-3 小时主线再排）

- 词云差异（原型 `game-compare.js` 已实现"词频差异放大"，可移植）。
- 对比表导出 csv。
- 每游戏小封面缩略图（Steam CDN `header.jpg`，带 fallback）。

### 7.5 分步落地顺序（每步可独立演示）

> 实现进度（2026-08-19）：原型卡片页 + 下方 Streamlit 图表对比视图 1-5 步均已实现（`app.py` render_compare + `db.py` 聚合方法 + `charts.py` 图表函数），含下钻链接；`AppTest` 双视图 0 异常。

1. **repo 聚合查询 + 口径确认**（`list_targets` / `opinion_matrix` / `sentiment_ratio`）
2. **KPI 行 + 堆叠条**
3. **热力图**（含兜底桶排除 + 占比/偏差两种模式）
4. **散点定位图 + 痛点表**
5. **下钻链接收尾**（点游戏/主题 → 跳转单目标看板）

> 符合项目"最快见到反馈"的风格：每一步都是可演示的增量。

## 九、一句话记忆

> **"偏差"是 P3 的灵魂，样本量是 P3 的底线，雷达图是 P3 的陷阱。**

按此思路，2-3 小时主线 + 1-2 个加分项，即可成为当前仪表盘最直接的洞察力增量。
